# Deploying Customer Web (Next.js)

This guide explains how to deploy your Next.js Customer Web application using either Static Export or Server-Side Rendering (SSR). Choose the deployment method based on your hosting environment and requirements.

## Choosing Your Deployment Method

<Note type="info">
  If you're deploying to shared hosting or a host that only serves static files,
  prefer the Static Export (static build). If you have a server or VPS with
  Node.js available and need dynamic pages or real-time features, choose
  Server-Side Rendering (SSR).
</Note>

    ### Static Export Deployment
    
    Best for:
    - Shared hosting environments
    - Static file hosting (Netlify, Vercel, GitHub Pages)
    - When Node.js server is not available
    - Simple deployments without dynamic requirements

    #### 1. Configure Static Export

    1. Open your `.env` file in the project root and set:
    ```env
    NEXT_PUBLIC_SSR=false
    ```

    2. Run locally website first and verify:
    ```cmd
    npm run dev
    ```

    #### 2. Build the Project

    ```bash
    npm run build
    ```

    This will create an `out` directory containing static files.

    #### 3. Deploy the Files

    Upload the entire contents of the `out` folder to your web server's public directory (e.g., public_html, www, etc.)

    ##### For cPanel Hosting:
    1. Access your cPanel
    2. Open File Manager
    3. Navigate to public_html
    4. Upload the contents of the `out` folder
    5. Ensure proper file permissions (typically 644 for files, 755 for directories)

    ##### For FTP Upload:
    1. Connect to your server using FTP client
    2. Navigate to your web root directory
    3. Upload all files from the `out` folder
    4. Maintain the folder structure exactly as is

    #### 4. Configure Web Server

    ##### Apache (.htaccess file):
    ```apache
    <IfModule mod_rewrite.c>
        RewriteEngine On
        RewriteBase /
        RewriteRule ^index\.html$ - [L]
        RewriteCond %{REQUEST_FILENAME} !-f
        RewriteCond %{REQUEST_FILENAME} !-d
        RewriteRule . /index.html [L]
    </IfModule>
    ```

    ##### Nginx (nginx.conf):
    ```nginx
    location / {
        try_files $uri $uri/ /index.html;
    }
    ```

    #### 5. Optional: FTP Auto-deploy

    If you'd like to automatically upload the generated static files to your server via FTP, the project includes an `ftp.js` file that accepts a configuration object like:

    ```javascript
    const config = {
      host: "your.ftp.server.com",
      user: "ftp-username",
      password: "ftp-password",
      port: 21,
      localRoot: __dirname + "/build",
      remoteRoot: "/",
      include: ["*", ".htaccess"],
      exclude: ["images/**"],
      deleteRemote: false,
    };
    ```

    Fill the values with your server credentials and settings. Then run:

    ```cmd
    npm run deploy
    ```

    This will upload the `out` folder to your server (if `localRoot` is set correctly and the FTP credentials are valid). Make sure `NEXT_PUBLIC_SSR=false` in your `.env` so the site is built as static output, and verify `localRoot` points to the folder containing the built static files.

    If the FTP credentials are incorrect the deploy will fail — check the terminal output for the error details.

    ### Server-Side Rendering Deployment

    Best for:
    - VPS or dedicated servers
    - Environments with Node.js support
    - Applications requiring dynamic content
    - Real-time data requirements

    #### 1. Configure SSR

    1. Open your `.env` file in the project root and set:
    ```env
    NEXT_PUBLIC_SSR=true
    ```

    #### 2. Server Prerequisites

    Install Node.js and PM2 on your server:

    ```bash
    # Update package list
    sudo apt update

    # Install Node.js
    curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
    sudo apt install -y nodejs

    # Verify installation
    node -v
    npm -v

    # Install PM2 globally
    sudo npm install -g pm2
    ```

    #### 3. Deploy Application

    1. Transfer your project files to the server:
    ```bash
    # Example using scp
    scp -r ./your-project-folder user@your-server:/path/to/destination
    ```

    2. Install dependencies and build:
    ```bash
    cd /path/to/your/project
    npm install
    npm run build
    ```

    #### 4. Configure PM2

    Create a PM2 configuration file `ecosystem.config.js`:

    ```javascript
    module.exports = {
      apps: [
        {
          name: 'customer-web',
          script: 'node_modules/next/dist/bin/next',
          args: 'start',
          instances: 'max', // or a number like 4
          exec_mode: 'cluster',
          autorestart: true,
          watch: false,
          max_memory_restart: '1G',
          env: {
            NODE_ENV: 'production',
            PORT: 3000
          }
        }
      ]
    }
    ```

    Start the application with PM2:
    ```bash
    pm2 start ecosystem.config.js
    ```

    Setup PM2 startup script:
    ```bash
    pm2 startup
    pm2 save
    ```

    #### 5. Configure Nginx as Reverse Proxy

    Create an Nginx configuration file:

    ```nginx
    server {
        listen 80;
        server_name your-domain.com;

        location / {
            proxy_pass http://localhost:3000;
            proxy_http_version 1.1;
            proxy_set_header Upgrade $http_upgrade;
            proxy_set_header Connection 'upgrade';
            proxy_set_header Host $host;
            proxy_cache_bypass $http_upgrade;
        }
    }
    ```

    Enable the configuration and restart Nginx:
    ```bash
    sudo ln -s /etc/nginx/sites-available/your-site /etc/nginx/sites-enabled/
    sudo nginx -t
    sudo systemctl restart nginx
    ```

    #### 6. SSL Configuration (Optional but Recommended)

    Install Certbot and obtain SSL certificate:
    ```bash
    sudo apt install certbot python3-certbot-nginx
    sudo certbot --nginx -d your-domain.com
    ```

    #### 7. Monitoring and Maintenance

    Monitor your application:
    ```bash
    pm2 status
    pm2 logs
    pm2 monit
    ```

    Update your application:
    ```bash
    git pull  # Get latest changes
    npm install
    npm run build
    pm2 reload all
    ```

## Environment Variables

Regardless of the deployment method, ensure your environment variables are properly set:

```env
NEXT_PUBLIC_SSR=true/false  # Depends on deployment method

NEXT_PUBLIC_ADMIN_PANEL_URL=https://your-admin-panel-url.com
```

## Deployment Checklist

Before deploying, verify:

- [ ] All environment variables are correctly set
- [ ] Build process completes successfully
- [ ] Admin Panel URL is correctly configured
- [ ] All API endpoints are properly configured
- [ ] Assets and images are loading correctly
- [ ] SSL certificate is installed (if required)
- [ ] DNS settings are configured properly

## Troubleshooting

### Static Export Issues

- If pages are not found, check your .htaccess or nginx configuration
- Verify all static assets are properly uploaded
- Check file permissions on your hosting server

### SSR Deployment Issues

- Check PM2 logs: `pm2 logs`
- Verify Node.js version compatibility
- Check Nginx error logs: `sudo tail -f /var/log/nginx/error.log`
- Ensure ports are not blocked by firewall
- Verify process has sufficient permissions
